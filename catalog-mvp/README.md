# Каталог 3D-обладнання: тестовий MVP

Чистий HTML/JS, без збірки. Сітка постерів, 3D відкривається по тапу для однієї моделі.

> Статус заливки: текстові файли в репозиторії, а бінарні (`models/nurofen-stand.glb`, 1,5 МБ, і `posters/nurofen-stand.webp`, 59 КБ) треба додати вручну в ці самі папки. Без них каталог покаже порожні картки.

## Структура
- `index.html` сторінка каталогу (фільтр за брендом, повноекранний 3D-перегляд)
- `catalog.json` дані каталогу (додати обладнання = додати запис)
- `models/` GLB, `posters/` WebP-постери
- `scripts/optimize.sh` оптимізація GLB з Meshy, `scripts/poster.py` програмний рендер постера

## Як запустити
Відкривати лише через http(s) (GitHub Pages або `python3 -m http.server`), не як `file://`: `fetch('catalog.json')` і завантаження GLB з файлу не працюють.

## Що зроблено і виміряно
| Показник | До | Після |
|---|---|---|
| Файл | 34,2 МБ | 1,5 МБ |
| Трикутники | 429 334 | 107 330 (ratio 0.25) |
| Текстури | 4096 JPEG (колір, нормаль), 2048 (metal/rough) | 2048 WebP, q80 |
| Стиснення геометрії | немає | meshopt |

Порядок у `optimize.sh`: resize 2048, webp, weld, simplify, meshopt. Бібліотека: `<model-viewer>` 4.3.1 (закріплено; 4.4.0 вийшла 2026-10-09, тобто менш ніж 2 тижні тому на момент створення).

## Рішення, що прийняті
- Каталог = постери (≈59 КБ), GLB і сама бібліотека вантажаться лише після тапу.
- Живий `<model-viewer>` створюється при відкритті і видаляється при закритті (щоб не тримати GPU).
- Вихідний 4K оригінал лишити в архіві окремо; на сайт іде лише 2K копія.

## Не перевірено (зробити першим)
1. **Жоден браузер у середовищі розробки не запускався.** Невідомо, чи `model-viewer` 4.3.1 коректно читає GLB з `EXT_meshopt_compression` + `EXT_texture_webp` (meshopt у документації підтримується, WebP не підтверджено окремо). Якщо модель не завантажується, спершу прибрати WebP-крок (залишити JPEG) і перезібрати.
2. Початкова орієнтація камери: невідомо, якою гранню модель повернута до глядача спочатку.
3. Поведінка кількох `model-viewer` на iOS Safari: у репозиторії проєкту є відкрита проблема про уповільнення. Схема «одна жива модель за раз» її обходить.
4. Офлайн для PWA (service worker, кешувати лише переглянуті моделі) не зроблено.

## Відомі особливості моделі (не наслідок оптимізації)
- На одній із бічних граней текст у текстурі від Meshy спотворений. Порівняння рендерів оригінальної і спрощеної сітки показало однаковий результат, тож спрощення цього не спричиняє.
- Дрібний текст на упаковках і нижня частина стенда розмиті (обмеження AI-текстур).
- Початок координат моделі по центру (min Y -0,95, max +0,95), а не внизу.
- Постер зроблений простим програмним рендером (пласке освітлення, без normal map), тому виглядає плоскіше за живу модель.
